## 2. PR #2 — 버그 수정

### 2-1. 일정 수정 시 태그가 갱신되지 않던 문제
- **위치:** `frontend/src/store/careScheduleStore.ts` `updateSchedule`
- **증상:** 일정을 수정하고 새로고침하면 돌봄 옵션(`care-option-tags`)과 엄마/아빠 구분(`parent-tags`)이 예전 값으로 되돌아갔습니다.
- **원인:** `addSchedule`은 태그를 저장하지만 `updateSchedule`은 저장소를 건드리지 않았습니다.
- **수정:** 수정 시에도 두 태그를 `addSchedule`과 같은 방식으로 갱신합니다. 값이 없으면 해당 일정의 태그를 지웁니다.

### 2-2. 맞벌이 시 돌봄 일정 요일 오류
- **위치:** `frontend/src/components/GapMatchPanel.tsx`
- **증상:** 부모 근무 블록 중 첫 번째만 보고 요일을 정해, 두 사람의 근무가 다르면 엉뚱한 요일에 돌봄 일정이 저장되었습니다.
- **수정:** 엄마와 아빠가 모두 등록되어 있으면 두 사람이 모두 근무하는 요일만 씁니다. 한쪽만 있으면 근무 요일 전체를 씁니다. 공백 계산(`data/gaps.ts`의 `computeGaps`)과 같은 기준입니다.

### 2-3. 당일 공백 중 첫 번째만 매칭하던 문제
- **위치:** `frontend/src/pages/Home.tsx`, `frontend/src/components/GapMatchPanel.tsx`
- **증상:** 아이에게 공백이 여러 개여도 첫 번째 공백만 매칭했습니다.
- **수정:** 공백마다 패널을 띄우고, 돌봄 옵션도 모든 공백에 대해 가져와 합칩니다. 체크 상태는 옵션의 일정 시간이 해당 공백과 겹칠 때만 체크된 것으로 봅니다. 한 옵션이 여러 공백에 걸쳐도 서로 영향을 주지 않습니다.

### 2-4. 예외 일정 N+1 요청 (백엔드 작업 필요)
- **현황:** 프론트는 일정 수만큼 예외 일정 API를 호출합니다(`careScheduleStore.ts`의 `loadAll`).
- **원인:** 백엔드에 일정별 조회 라우트만 있고 일괄 조회 API가 없습니다.
- **요청 문서:** `docs/backend-request-exceptions-batch.md` (`GET /schedules/exceptions` 제안)
- **프론트 후속:** 백엔드가 API를 만들면 `loadAll`의 호출을 한 번으로 바꿉니다.

### 2-5. 비로그인 지역 필터 불일치 (재현되지 않음)
- 리뷰에 적힌 "비로그인 시 텍스트 입력" 문제는 현재 코드에 없습니다. 지역 필터는 `Find.tsx`의 칩/드롭다운 하나뿐이고 로그인 여부와 관계없이 같습니다.
- 수정하지 않았습니다. 해당 리뷰가 어느 브랜치를 기준으로 했는지 확인이 필요합니다.

## 3. PR #3 — 디자인 개선

공통 방향은 **보조 글자 대비 확보, 터치 크기 확보, 정보 위계 정리**입니다. 기존 아이보리·그린 토큰과 Pretendard 폰트는 그대로 씁니다.

### 3-1. 메인 (`Home.tsx`)
- 보조 글자 색을 `text-ink-3`에서 `text-ink-2`로 바꿨습니다. 이전 대비는 3.3~3.8:1이라 WCAG AA(4.5:1)에 못 미쳤고, 바뀐 뒤 6.5~7.5:1입니다.
- 지역 선택과 구/군 입력 칸을 최소 44px 높이로 맞췄습니다.
- 히어로와 섹션 위아래 여백을 모바일에서 줄였습니다(md 이상은 기존 값).

### 3-2. 돌봄 찾기 (`Find.tsx`)
- 비용을 운영시간 줄에서 빼서 카드 오른쪽 위 배지로 표시합니다. 무료는 초록색, 유료는 회색입니다.
- 결과가 없을 때 "지역, 학년, 시간 조건을 바꿔 보세요" 안내와 "조건 초기화" 버튼을 보여줍니다. 조건이 있을 때만 버튼이 나옵니다.
- 보조 글자 색을 `text-ink-2`로 바꿨습니다.

### 3-3. 기관 상세 (`CareOptionDetail.tsx`)
- 운영 시간, 비용, 대상 학년을 상단에 타일 세 개로 먼저 보여줍니다.
- 상단 설명에서 운영 시간과 비용을 빼서 중복을 없앴습니다. 설명에는 유형만 남깁니다.
- 목록은 유형, 주소, 전화만 남겼습니다.
- 전화 버튼 최소 높이 44px.

## 4. 검증 현황

| 항목 | 상태 |
|---|---|
| `npm run build` (타입체크 포함) | 통과 (PR #2, PR #3 모두) |
| `npm run lint` | 변경 파일에서 새 경고 없음 |
| 데스크톱 화면 확인 (메인, 돌봄 찾기, 기관 상세) | 로컬 개발 서버에서 확인 |
| 모바일 너비 화면 확인 | **미확인** |
| 로그인 후 기능 (일정 수정 후 새로고침, 맞벌이 요일, 공백 여러 개) | **미확인** — 로그인은 카카오/네이버 OAuth라 로컬에서 재현이 어려움 |

**로그인 기능 확인 방법 (참고):** 로컬 개발 서버의 API 주소(`.env`의 `VITE_API_URL`)는 운영 백엔드를 가리킵니다. 로그인 후 확인이 필요하면 이 주소와 OAuth 리다이렉트 설정을 같이 확인해야 합니다.

## 5. 남은 과제

1. **필터 칩 터치 크기:** `Chip` 컴포넌트가 44px에 못 미칩니다. 공통 컴포넌트라 여러 화면에 영향을 줍니다.
2. **모바일 너비 점검:** 375px, 768px에서 메인, 돌봄 찾기, 상세 화면을 확인해야 합니다.
3. **히어로 재구성 (보류):** 하루 일정 그림이 포함된 소개 영역을 검토했지만, 팀 방향을 정한 뒤 진행하기로 했습니다.
4. **예외 일정 일괄 조회:** 백엔드 API 구현 후 프론트 호출을 교체합니다.
5. **배포 검증:** 실제 배포 주소에서 기능 테스트와 OAuth 로그인 확인이 필요합니다. 자세한 내용은 `docs/frontend-deployment-report.txt`에 있습니다.

## 7. 로컬에서 확인하는 방법

```bash
cd frontend
npm install
npm run dev     # http://localhost:5173
npm run build   # 타입체크 + 빌드
npm run lint
```

백엔드 없이 볼 수 있는 화면은 메인, 돌봄 찾기, 기관 상세입니다. 일정 등록과 맞춤 매칭은 로그인 후에만 보입니다.
