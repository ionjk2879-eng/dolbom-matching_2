프론트엔드 배포 점검 (2026-10-08 최신화)

React 19 + TypeScript + Vite 8 기반이며, Zustand로 상태를, Naver Maps API v3로 지도를 연동했습니다.
배포 주소는 https://dolbom-matching-2.pages.dev 이고, main 브랜치에 머지하면 약 1분 안에 자동 배포됩니다(10/8 PR #26 머지 후 40초 만에 반영 확인).
frontend/wrangler.jsonc에 Workers 정적 자산 설정(SPA 라우팅: not_found_handling = single-page-application)도 있습니다.
백엔드 주소는 VITE_API_URL로 관리해서 로컬은 .env, 운영은 .env.production으로 분리했고, 시크릿은 저장소에 두지 않았습니다.
npm run build(tsc -b + Vite 빌드)와 npm run lint(oxlint 1.86)가 모두 경고 없이 통과합니다(10/8 확인).
빌드 결과물 중 이미지 두 개(login-hero 약 2.0MB, logo 약 0.8MB)가 커서 WebP 변환으로 로딩 개선이 가능하지만, 아직 적용하지 않았습니다.
배포 사이트에서 카카오 로그인, 일정·예외 저장과 되돌리기, 공백 계산, 돌봄 찾기 전체 목록(2,237곳)이 동작하는 것을 확인했습니다(10/8).
로컬 프론트(localhost:5173)에서는 로그인 후 배포 주소로 돌아가서 로그인이 안 됩니다. 백엔드 요청서: docs/backend-request-oauth-return-url.md
네이버 로그인 왕복과 회원가입 직후 첫 화면은 아직 직접 확인하지 않았습니다.
오류 시에는 Workers 로그와 브라우저 개발자 도구로 원인을 찾고, git revert 후 main에 머지하면 이전 상태로 다시 배포됩니다(실제 롤백은 아직 해 보지 않음).
